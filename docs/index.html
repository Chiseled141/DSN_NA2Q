How the Agent Picks Actions

Algorithm Concept

Think of it like learning to play a game: At first, you try random moves to see what works. As you learn, you start making smarter choices based on experience.

  • Explore (random): Try new things to learn what works
  • Exploit (smart): Pick the best move you know
  • Less random over time: Start 100% random → end 5% random

Code Details

The select_actions() method implements the ε-greedy policy:

  • Line 3-5: Convert observations to tensor format
  • Line 7-8: Initialize GRU hidden states if needed
  • Line 10-12: Forward pass through Q-network
  • Line 14-16: Mask invalid actions with -infinity
  • Line 18-22: Random vs greedy action selection

def select_actions(self, observations, prev_actions=None, avail_actions=None, evaluate=False):
    """Select actions for all agents using ε-greedy policy."""
    with torch.no_grad():
        # Convert numpy to tensor and add batch dimension
        obs_tensor = torch.FloatTensor(observations).unsqueeze(0).to(self.device)
        # Shape: [1, n_agents, obs_dim]
        
        # Initialize hidden states if needed
        if self.hidden_states is None:
            self.init_hidden(1)
        
        # Get Q-values from GRU-based network
        q_values, self.hidden_states = self.model.get_q_values(
            obs_tensor, self.hidden_states, prev_actions_tensor
        )
        q_values = q_values.squeeze(0)  # [n_agents, n_actions]
        
        # Mask unavailable actions (set Q to -inf)
        if avail_actions is not None:
            avail_mask = torch.FloatTensor(avail_actions).to(self.device)
            q_values[avail_mask == 0] = -float('inf')
        
        # ε-greedy action selection
        if not evaluate and np.random.random() < self.epsilon:
            # EXPLORE: Random action
            actions = np.random.randint(0, self.n_actions, self.n_agents)
        else:
            # EXPLOIT: Best action according to Q-values
            actions = q_values.argmax(dim=-1).cpu().numpy()
    
    return actions

The Agent's Brain (Q-Network)

Algorithm Concept

This is like a camera's memory: It remembers what it saw before and uses that to decide "how good is each action right now?" Higher score = better action.

  • Sees: Current view (where are targets? how far?)
  • Remembers: What happened in previous steps (using GRU memory)
  • Outputs: A score for each action (LEFT: 5.2, STAY: 3.1, RIGHT: 7.8)

Code Details

The AgentQNetwork class architecture:

  • fc1: Input layer transforms observations (obs_dim → 64)
  • gru: Memory cell retains temporal context
  • fc2: Output layer produces Q-values for all actions

class AgentQNetwork(nn.Module):
    """Individual Agent Q-Network with GRU memory."""
    
    def __init__(self, obs_dim, n_actions, hidden_dim=64, rnn_hidden_dim=64):
        super().__init__()
        # Layer 1: Combines observation + previous action
        self.fc1 = nn.Linear(obs_dim + n_actions, hidden_dim)
        # Layer 2: GRU memory cell
        self.gru = nn.GRUCell(hidden_dim, rnn_hidden_dim)
        # Layer 3: Output Q-values for each action
        self.fc_q = nn.Linear(rnn_hidden_dim, n_actions)
    
    def forward(self, obs, hidden_state, prev_action=None):
        # Prepare previous action (one-hot encoding)
        if prev_action is None:
            prev_action = torch.zeros(batch_size, self.n_actions)
        elif prev_action.dim() == 1:
            prev_action = F.one_hot(prev_action, self.n_actions).float()
        
        # Combine observation and previous action
        x = torch.cat([obs, prev_action], dim=-1)
        x = F.relu(self.fc1(x))  # [batch, hidden_dim]
        
        # Update memory using GRU
        hidden_state = self.gru(x, hidden_state)
        
        # Compute Q-values for each action
        q_values = self.fc_q(hidden_state)  # [batch, n_actions]
        
        return q_values, hidden_state

Team Score Calculator (Mixer)

Algorithm Concept

How do we get a team score from individual scores? The mixer adds up everyone's contribution, but some cameras matter more than others depending on the situation.

  • Add up scores: Camera 1: 5pts + Camera 2: 3pts + Camera 3: 7pts = 15pts total
  • Attention: "Camera 3 is tracking the most important target, give it more weight!"
  • Fair credit: Know exactly who helped the team win

Code Details

The NA2QMixer implements value decomposition:

  • gam_attention: Computes agent importance weights
  • forward(): Aggregates weighted Q-values into global Q
  • agent_semantics: Provides context for attention calculation

class NA2QMixer(nn.Module):
    """NA²Q Mixer with GAM-based Value Decomposition."""
    
    def forward(self, agent_q_values, state, agent_semantics):
        # Step 1: Compute Shape Function Outputs
        shape_outputs = []
        
        # Order-1: Individual contributions f_i(Q_i)
        for i in range(self.n_order1):
            q_i = agent_q_values[:, i:i+1]
            shape_outputs.append(self.order1_shapes[i](q_i))
        
        # Order-2: Pairwise interactions f_ij(Q_i, Q_j)
        for idx, (i, j) in enumerate(self.pairwise_indices):
            q_ij = torch.cat([agent_q_values[:, i:i+1], 
                              agent_q_values[:, j:j+1]], dim=-1)
            shape_outputs.append(self.order2_shapes[idx](q_ij))
        
        # Step 2: Compute Attention Weights
        state_enc = self.state_encoder(state)
        semantic_enc = self.semantic_encoder(agent_semantics.view(batch_size, -1))
        attention_weights = F.softmax(self.attention_net(
            torch.cat([state_enc, semantic_enc], dim=-1)), dim=-1)
        
        # Step 3: Weighted sum + bias = Q_total
        q_total = (attention_weights * torch.cat(shape_outputs, dim=-1)).sum(
            dim=-1, keepdim=True) + self.bias_net(state)
        
        return q_total, attention_weights, shape_outputs

How the Agent Learns (Training)

Algorithm Concept

Learning from trial and error: The agent tries actions, gets rewards, and updates its brain to make better predictions next time.

  • Goal: "My prediction was 5 points, but I got 8 → I need to predict higher next time!"
  • Two brains: One learns fast (online), one is stable (target) — prevents wild swings
  • Smooth updates: Slowly mix the fast brain into the stable one (0.5% per step)

Code Details

The train_step_fn() implements Double DQN:

  • td_error: Difference between predicted and actual Q-values
  • loss.backward(): Backpropagation updates network weights
  • soft_update(): Gradually syncs target network (tau=0.005)
na2q/models/agent.py

def train_step_fn(self, batch):
    """Perform one training step on a batch of experience."""
    # Unpack batch: observations, actions, rewards, states, dones
    observations = torch.as_tensor(batch["observations"], device=device)
    actions = torch.as_tensor(batch["actions"], device=device)
    rewards = torch.as_tensor(batch["rewards"], device=device)
    
    # Process sequence through time (unroll GRU)
    with torch.amp.autocast(device_type, enabled=self.use_amp):
        for t in range(seq_len):
            # Forward pass through ONLINE model
            result = self.model(obs_t, hidden, state_t, actions_t)
            q_totals.append(result['q_total'])
            vae_losses.append(result['vae_loss'])  # VAE loss
            
            # DOUBLE DQN: online selects, target evaluates
            with torch.no_grad():
                next_q, _ = self.model.get_q_values(next_obs, target_hidden)
                next_actions = next_q.argmax(dim=-1)
                target_result = self.target_model(next_obs, next_actions)
                target_q_totals.append(target_result['q_total'])
    
    # TD target: r + γ × (1 - done) × Q_target
    targets = rewards + self.gamma * (1 - dones) * target_q_totals
    
    # Combined loss: TD + VAE
    td_loss = F.smooth_l1_loss(q_totals, targets)
    total_loss = td_loss + self.vae_loss_weight * vae_loss
    
    # Backpropagate and update
    total_loss.backward()
    self.optimizer.step()
    self.soft_update_target(tau=0.005)  # Polyak averaging

How Rewards Work

Algorithm Concept

The team gets points for covering targets: More targets in view = more reward. The goal is to maximize total coverage.

  • Target covered: +1 point per target in any camera's view
  • Coverage rate: (targets covered / total targets) × 100%
  • Team goal: Get as close to 100% coverage as possible

Code Details

The compute_reward() function calculates team reward:

  • Nested loops: Check each target against all sensors
  • can_see(): Field-of-view geometry check
  • break: Avoid double-counting covered targets
environments/dsn_env.py Python 
def compute_reward(self):
    """Calculate team reward based on target coverage."""
    covered = 0
    
    # Check each target
    for target in self.targets:
        # Is this target in ANY camera's field of view?
        for sensor in self.sensors:
            if sensor.can_see(target):
                covered += 1
                break  # Don't double-count
    
    # Coverage rate: e.g., 4/5 = 80%
    coverage_rate = covered / len(self.targets)
    
    # Reward = coverage rate (0.0 to 1.0)
    return coverage_rate

The Simulation World (Environment)

Algorithm Concept

Imagine a security control room: You have cameras on a map watching moving targets. The environment is the "game world" where agents practice.

  • Map: A 2D area where cameras and targets exist
  • Cameras (Sensors): Can rotate left, stay, or rotate right
  • Targets: Move around randomly — cameras try to track them

Code Details

The DSNEnvironment class simulates the world:

  • __init__: Creates sensors and targets with random positions
  • step(actions): Applies camera rotations and target movements
  • Field of View: Each camera sees only a pie-slice shaped area
environments/dsn_env.py Python 
class DSNEnvironment:
    """Directional Sensor Network simulation environment."""
    
    def __init__(self, n_sensors=5, n_targets=5, fov_angle=60):
        # The map size (100x100 units)
        self.map_size = 100
        
        # Create cameras with random positions
        self.sensors = [Sensor(
            x=random.uniform(0, self.map_size),
            y=random.uniform(0, self.map_size),
            fov=fov_angle  # Each camera sees 60° arc
        ) for _ in range(n_sensors)]
        
        # Create targets that move around
        self.targets = [Target(
            x=random.uniform(0, self.map_size),
            y=random.uniform(0, self.map_size)
        ) for _ in range(n_targets)]
    
    def step(self, actions):
        """Take one step in the simulation."""
        # Each camera rotates based on its action
        for sensor, action in zip(self.sensors, actions):
            if action == 0:      # Rotate LEFT
                sensor.rotate(-10)
            elif action == 1:   # STAY still
                pass
            elif action == 2:   # Rotate RIGHT
                sensor.rotate(+10)
        
        # Move targets randomly
        for target in self.targets:
            target.random_walk()
        
        # Calculate reward and return new observations
        reward = self.compute_reward()
        obs = self.get_observations()
        return obs, reward

One Training Episode (Episode)

Like playing one round of a game: The episode starts, agents take actions, get rewards, and learn. Then we reset and play again.

  • Reset: Put cameras and targets in new random positions
  • 100 Steps: Each step, cameras decide where to look
  • Collect Experience: Save what happened (state, action, reward)
  • Learn: After the episode, train the neural network on this experience
training/episode.py Python 
def run_episode(env, agent, max_steps=100):
    """Run one complete training episode."""
    
    # Step 1: Reset environment to starting state
    observations = env.reset()
    episode_reward = 0
    experience_buffer = []
    
    # Step 2: Run for 100 timesteps
    for step in range(max_steps):
        # Each camera picks an action
        actions = agent.select_actions(observations)
        
        # Execute actions in environment
        next_obs, reward, done = env.step(actions)
        
        # Save this experience for learning
        experience_buffer.append({
            'obs': observations,
            'actions': actions,
            'reward': reward,
            'next_obs': next_obs
        })
        
        # Track total reward
        episode_reward += reward
        observations = next_obs
        
        if done:
            break
    
    # Step 3: Learn from the episode
    agent.learn(experience_buffer)
    
    return episode_reward

The Boss (Coordinator)

Algorithm Concept

Think of a team manager: The boss sees the whole field and decides "Camera 1, you track Target A. Camera 2, you track Target B."

  • Sees everything: All cameras and all targets at once
  • Simple decisions: "Should Camera 1 track Target 2? Yes or No"
  • Task assignment: Makes sure no one is left out

Code Details

The A3C_Multi class coordinates all agents:

  • encoder: Transforms raw poses into features
  • attention: Aggregates information across all agents
  • actor: Binary decisions for target assignment
hitmac/models.py Python 
class A3C_Multi(torch.nn.Module):
    """Multi-agent Coordinator for HiT-MAC."""
    
    def __init__(self, n_sensors, n_targets, n_actions, args, device):
        super().__init__()
        # Linear encoder: pose_dim → lstm_out
        self.encoder = EncodeLinear(self.pose_dim, lstm_out, head_name, device)
        # Attention: aggregates all features
        self.attention = AttentionLayer(feature_dim, lstm_out, device)
        # Actor: binary decisions (track target or not)
        self.actor = PolicyNet(feature_dim, spaces.Discrete(2), head_name, device)
        # Critic: Shapley value-based or standard
        if 'shap' in head_name:
            self.ShapleyVcritic = AMCValueNet(feature_dim, head_name, 1, device)
    
    def forward(self, inputs, test=False):
        # Step 1: Encode each observation
        feature_target = self.encoder(inputs)
        # Step 2: Reshape for attention [1, n_agents*n_targets, feature_dim]
        feature_target = feature_target.reshape(-1, self.encoder.feature_dim).unsqueeze(0)
        # Step 3: Apply attention
        feature, global_feature = self.attention(feature_target)
        # Step 4: Actor decides assignments
        actions, entropies, log_probs = self.actor(feature.squeeze(), test)
        actions = actions.reshape(self.num_agents, self.num_targets, -1)
        # Step 5: Critic estimates value (Shapley or standard)
        if 'shap' in self.head_name:
            values = self.ShapleyVcritic(feature.squeeze(), actions)
        else:
            values = self.critic(global_feature)
        return values, actions, entropies, log_probs

The Workers (Executors)

Algorithm Concept

Each camera has its own operator: Once the boss assigns a target, the worker figures out how to actually move the camera to track it.

  • One worker per camera: Each camera has its own controller
  • Simple moves: Rotate LEFT, STAY still, or rotate RIGHT
  • Focus on assigned target: Only cares about what the boss told it to track

Code Details

The A3C_Single class controls individual agents:

  • encoder: Processes local observation
  • lstm: Maintains temporal memory for each agent
  • actor: Outputs action probabilities (LEFT/STAY/RIGHT)
hitmac/models.py Python 
class A3C_Single(torch.nn.Module):
    """Single-agent Executor for HiT-MAC."""
    
    def __init__(self, n_sensors, n_targets, n_actions, args, device):
        super().__init__()
        obs_dim = 4  # 4 features per target (sensor_id, target_id, distance, angle)
        # Attention encoder: processes observation → feature vector
        self.encoder = AttentionLayer(obs_dim, args.lstm_out, device)
        # Critic: estimates state value V(s)
        self.critic = ValueNet(args.lstm_out, args.model, 1)
        # Actor: outputs action probabilities π(a|s)
        self.actor = PolicyNet(args.lstm_out, n_actions, args.model, device)
    
    def forward(self, inputs, test=False):
        data = Variable(inputs, requires_grad=True)
        # Attention encoder: [batch, n_targets, obs_dim] → feature
        _, feature = self.encoder(data)
        # Actor: feature → action
        actions, entropies, log_probs = self.actor(feature, test)
        # Critic: feature → value
        values = self.critic(feature)
        return values, actions, entropies, log_probs

Fair Credit (Shapley Values)

Algorithm Concept

Who really helped the team? Imagine 3 friends order pizza together. Shapley values figure out how much each person should pay based on what they actually ate.

  • Fair split: Camera that covered 3 targets gets more credit than one that covered 1
  • Your contribution: "What if you weren't here? How much worse would we do?"
  • Smart shortcut: Uses attention to estimate quickly (not slow math)

Code Details

The AMCValueNet computes Shapley values:

  • coalition: Builds up the team one agent at a time
  • attention: Summarizes coalition features
  • critic_linear: Estimates marginal contribution per agent
hitmac/models.py Python 
class AMCValueNet(nn.Module):
    """Attention-based Multi-agent Credit (Shapley) Value Network."""
    
    def forward(self, x, goal):
        _, feature_dim = x.shape
        value = []
        coalition = x.view(-1, feature_dim)
        n = coalition.shape[0]
        
        # First agent: no coalition context yet
        feature = torch.zeros([self.feature_dim]).to(self.device)
        value.append(self.critic_linear(torch.cat([feature, coalition[0]])))
        
        # Subsequent agents: marginal contribution given previous agents
        for j in range(1, n):
            # Use attention to get coalition summary
            _, feature = self.attention(coalition[:j].unsqueeze(0))
            # Marginal contribution: Value(coalition + agent_j) - Value(coalition)
            value.append(self.critic_linear(torch.cat([feature.squeeze(), coalition[j]])))
        
        # Sum all marginal contributions = team value
        value = torch.cat(value).sum()
        return value.unsqueeze(0)

Actor-Critic Learning

Algorithm Concept

Two friends learning together: The Actor tries different actions, the Critic tells it "that was good!" or "try something else."

  • Actor: Picks actions (like a player choosing moves)
  • Critic: Rates how good each situation is (like a coach)
  • Advantage: "Was that action better or worse than average?"

Code Details

The sample_action() implements policy sampling:

  • softmax: Converts logits to action probabilities
  • entropy: Measures exploration (high = uncertain)
  • test mode: Greedy selection vs stochastic sampling
hitmac/models.py Python 
def sample_action(mu_multi, sigma_multi, device, test=False):
    """Sample discrete action from policy logits."""
    logit = mu_multi
    
    # Softmax: convert logits to probabilities (sum to 1)
    prob = F.softmax(logit, dim=-1)
    # Log softmax for numerical stability
    log_prob = F.log_softmax(logit, dim=-1)
    
    # Entropy = -sum(p * log(p))
    # High entropy = uncertain/exploring, low entropy = confident
    entropy = -(log_prob * prob).sum(-1, keepdim=True)
    
    if test:
        # Greedy: pick action with highest probability
        action = prob.max(-1)[1].data
        action_env = action.cpu().numpy()
    else:
        # Stochastic: sample from distribution
        action = prob.multinomial(1).data
        log_prob = log_prob.gather(1, Variable(action))
        action_env = action.squeeze(0)
    
    return action_env, entropy, log_prob

Two-Level Control (Hierarchy)

Algorithm Concept

Like a company structure: The CEO (Coordinator) makes high-level plans, then managers (Executors) handle the details.

  • Level 1 - Coordinator: "Who should track what?" (task assignment)
  • Level 2 - Executors: "How do I move to track my target?" (motor control)

Code Details

The HiTMACPlayer class manages the hierarchy:

  • coordinator: Multi-agent A3C network for high-level policy
  • executors: List of single-agent A3C networks for low-level control
  • act(): Cascades decisions from Coordinator down to Executors
hitmac/player.py Python 
class HiTMACPlayer:
    """Two-level hierarchical multi-agent controller."""
    
    def __init__(self, n_cameras, n_targets):
        # Level 1: One coordinator sees everything
        self.coordinator = A3C_Multi(
            n_cameras=n_cameras,
            n_targets=n_targets
        )
        
        # Level 2: One executor per camera
        self.executors = [A3C_Single() 
                         for _ in range(n_cameras)]
    
    def act(self, observation):
        """Hierarchical decision making."""
        # Step 1: Coordinator assigns targets
        assignments = self.coordinator(observation)
        # assignments[i] = target ID for camera i
        
        # Step 2: Each executor moves its camera
        actions = []
        for i, executor in enumerate(self.executors):
            # Executor only sees its own camera + assigned target
            local_obs = get_local_observation(observation, i, assignments[i])
            action = executor(local_obs)  # LEFT/STAY/RIGHT
            actions.append(action)
        
        return actions

Asynchronous Training (A3C)

Algorithm Concept

Many workers learning in parallel: Instead of one agent learning slowly, multiple workers play the game simultaneously and share what they learn.

  • Parallel Workers: 4-16 agents playing the game at the same time
  • Shared Brain: All workers update the network parameters
  • Speed: Learns much faster and more stably than single agents

Code Details

The train_worker() function implements A3C:

  • shared_model: Global network stored in shared memory
  • local_model: Worker's private copy for collecting experience
  • sync: Periodically copies global weights to local model
hitmac/train.py Python 
def train_worker(worker_id, shared_model, optimizer):
    """One A3C worker training asynchronously."""
    
    # Each worker has its own copy of the environment
    env = DSNEnvironment()
    local_model = HiTMACPlayer()
    
    while True:
        # Sync local model with shared model
        local_model.load_state_dict(shared_model.state_dict())
        
        # Collect n_steps of experience
        states, actions, rewards = [], [], []
        state = env.reset()
        
        for step in range(n_steps):
            action = local_model.act(state)
            next_state, reward, done = env.step(action)
            
            states.append(state)
            actions.append(action)
            rewards.append(reward)
            state = next_state
        
        # Compute advantage and policy gradient
        returns = compute_returns(rewards, gamma=0.99)
        advantage = returns - local_model.value(states)
        
        # Update shared model (thread-safe)
        loss = policy_loss + value_loss - entropy_bonus
        optimizer.zero_grad()
        loss.backward()
        
        # Apply gradients to shared model
        for local_p, shared_p in zip(local_model.parameters(), 
                                       shared_model.parameters()):
            shared_p._grad = local_p.grad
